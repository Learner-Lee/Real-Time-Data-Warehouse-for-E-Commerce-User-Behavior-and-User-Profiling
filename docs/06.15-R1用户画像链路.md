# 步骤 6.15 计划：用户画像链路（先用模拟数据跑通）

- 日期：2026-11-11
- 对应简历：「基于 DWS 层沉淀 50+ 用户行为特征，用 RFM + K-Means 把用户分成 6 类，XGBoost 复购预测 AUC 达 0.82，结果回写为画像标签」
- 目标：把「DWS 用户表 → 特征 → 分群 + 复购模型 → 标签写回 Doris」整条链路跑通。**数字以实际跑出的为准**，不往简历的数字上凑。

## 先说清楚：模拟数据能证明什么、不能证明什么

- 已确认的数据情况：Doris ODS 9 天、50 万条、7,797 个用户；每天约 160 个下单用户；中位数用户只有 1 条行为，最多的一个用户有 19 万条（幂律分布）。
- 生成器（`data/gen_synthetic.py`）里，每条行为是不是购买，是按固定概率 2.1% 随机抽的，和用户之前做过什么无关。所以「将来会不会买」**只取决于活跃度**。
- 因此：
  - **能证明**：链路通了，没有特征穿越，分群和标签能写回，代码换成真实数据后可以直接复用。
  - **不能证明**：模型学到了真实的复购规律。为了看清这一点，加一个「只用行为次数一个特征」的基线：如果 XGBoost 和它差不多，就说明学到的只是活跃度。

## 做法

| 步骤 | 内容 | 落在哪 |
|---|---|---|
| 1. 用户 × 天 DWS | 从 ODS 按「用户 × 天」汇总：各类行为次数、浏览商品数和类目数、活跃小时数、夜间行为数、首次 / 末次行为时间、最后购买时间 | Doris `dws_user_behavior_1d`（UNIQUE KEY，可重跑） |
| 2. 用户特征 | 从 DWS 用户表、MySQL 订单、用户维表算出 50 个以上特征，每个特征都有中文说明，写成 Doris 表的列注释 | Doris `dws_user_feature`，按「截止日期 × 用户」存 |
| 3. RFM + K-Means | 对 9 天内下过单的用户算 R（距最后一次购买的天数）、F（订单数）、M（支付金额），做经典 RFM 八类；再对标准化后的 RFM 做 K-Means，K 用肘部法和轮廓系数在 2–10 之间选 | 写进标签表 |
| 4. 复购模型 | 特征窗口 3 天，预测后 3 天是否购买。**按时间切分**：训练用 11-25～11-27 的特征、11-28～11-30 的标签；测试用 11-28～11-30 的特征、12-01～12-03 的标签。报告 AUC、PR-AUC，并和活跃度基线对比；另外单独算「窗口内已购买用户」的 AUC，这才是严格意义上的复购 | 报告 |
| 5. 回写标签 | 每个用户一行：RFM 分值和类别、K-Means 分群和名称、未来 3 天购买概率和等级 | Doris `ads_user_profile_tag` |

- 代码放在 `mvp/user_profile/`（不叫 profile，避免和 Python 自带的 profile 模块重名），用 `bin/profile.sh` 一键运行（建表 → 生成 DWS → 特征 → 模型 → 标签 → 报告），可重复运行。
- **防穿越**：特征只用截止时间之前的数据；订单的退款状态按 `update_time` 判断，截止时间之后才发生的退款不算。

## 已知限制

- M（消费金额）用的是模拟的商品价格，真实 UserBehavior 数据里也没有价格。
- 数据只有 9 天，窗口只能取 3 天。

# 结果（2026-11-11）

- **链路跑通**：`bash bin/profile.sh` 一条命令约 15 秒跑完：建表 → 从 ODS 生成 `dws_user_behavior_1d`（18,118 行、7,798 个用户，行为合计 50 万条，和 ODS 一致）→ 55 个特征写进 `dws_user_feature` → 分群和模型 → 7,798 人的标签写进 `ads_user_profile_tag` → 报告。可以重复运行。
- **和简历描述对照**：

| 简历 | 实际（模拟数据） | 说明 |
|---|---|---|
| 50+ 用户行为特征 | **55 个**，每个都有中文说明（写在 Doris 列注释里） | ✅ 对得上 |
| 分成 6 类 | 轮廓系数在 3–8 里选出 **K = 5**；如果不限范围，K = 2 最高 | ❌ 是 5 类；数字由数据决定，不能硬凑成 6 |
| 复购预测 AUC 0.82 | 按时间切分的测试集 **AUC 0.910**，但「只用行为次数」的基线也是 **0.911** | ⚠️ 模型没有比基线强：模拟数据的购买只和活跃度有关 |
| 结果回写为画像标签 | `ads_user_profile_tag`：RFM 分值和八类、K-Means 分群、未来 3 天购买概率和等级 | ✅ |

## 过程中的发现

1. **第一版模型过拟合**：训练集 AUC 0.99，测试集 0.87，还**不如只用行为次数的基线（0.91）**。加了「只在训练集内部留 30% 验证」的小范围调参（深度 2–4、最小叶子权重 5/20、树 100/300 棵），选出 max_depth=2、min_child_weight=20、100 棵树。之后训练集 0.93、测试集 0.91，和基线持平。测试集全程没参与调参。
   - 面试可讲：**拿基线做对照**，才发现第一版的「好成绩」其实不如一条规则；模型和基线持平，说明数据里只有活跃度这一个信号。
2. **数据极度偏斜**：9 天买过的只有 669 人；最活跃的 23 人平均 377 单、3.4 万元（幂律生成的「超级用户」），自成一群。经典 RFM 八类只出现了 4 类，因为 F、M 的平均值被少数人拉得很高。
3. **概率偏高**：为平衡正负样本加了权重，输出概率整体偏高（没买过的访客平均 0.19，实际购买比例约 6%），所以「高 / 中 / 低」按排名划（前 10% / 10–30% / 其余），不按绝对值。要当真实概率用，需要再做校准。
4. **Doris 的 VARCHAR 按字节算长度**：`近 3 天未活跃` 占 18 个字节，第一次写入时超过了 VARCHAR(16)，在严格模式下被拒绝。已经把中文列放宽。

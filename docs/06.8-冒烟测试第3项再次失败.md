# 步骤 6.8 记录：冒烟测试第 3 项再次失败

- 日期：2026-11-04
- 现象：Kafka、MySQL CDC 两项通过，「Kafka 关联 HBase 维表」一项失败：期望 gold，实际为空
- 结果：不是 HBase 连接器的问题，是 **slot 不够**。已给脚本加防护，重跑三项全部通过

## 结论

冒烟测试在两个 SSH 窗口里各跑了一次（17:25 同时开着 pts/0、pts/1，两次提交前后差约 3.5 秒）：
- 一次要 3 个作业、3 个 slot，两次共 6 个，而 TaskManager 只有 4 个 slot；
- 两份 Kafka、两份 CDC 作业先拿到了 slot，所以前两项通过；
- 两份 HBase 作业都报 `Could not fulfill resource requirements`，一直在重启，从未运行，所以 Doris 里没有结果。

## 证据

| 来源 | 看到的内容 |
|---|---|
| `flink list -a` | `smoke-kafka-doris`、`smoke-mysql-cdc-doris`、`smoke-hbase-lookup-doris` 各有 **2 个**作业 |
| JobManager 日志 | 6 次 `Received JobGraph submission`，按 A/B 交替：17:27:02、05、06、09、10、13 |
| JobManager 日志 | HBase 作业 `2c1f13…`：`Could not fulfill resource requirements` → RESTARTING，反复循环 |
| TaskManager 日志 | 这段时间没有任何 HBase 查询或 ZooKeeper 报错，说明作业根本没运行到 Lookup |
| `/data/smoke/*.log` | 每个文件里只有 1 个 Job ID：两次运行写的是同一个日志文件，后一次把前一次覆盖了，所以只看日志看不出提交了两次 |

## 修复（`setup/smoke/run-smoke.sh`）

| 防护 | 做法 |
|---|---|
| 同时只能跑一份 | 用 `flock` 锁 `/data/smoke/.lock`，第二份直接报错：「已经有一份冒烟测试在运行（可能在另一个 SSH 窗口里）」 |
| 提交前检查空闲 slot | 从 Flink REST `/overview` 读 `slots-available`，不足 3 个就报错，并提示先停 R1 MVP 作业 |

README 的排错表也补了一句：第 3 项失败时，先排除 slot 不够。

## 验证

- 起第一份后 3 秒再起第二份：第二份立刻被锁挡住。
- 第一份三项全部通过，结束时取消了 3 个测试作业。

## 面试可以怎么讲

> 「排查时我先看 JobManager 日志，而不是直接怀疑连接器。看到同名作业提交了两次，HBase 作业一直报资源不足、根本没跑起来。所以症状是『结果为空』，原因却是资源调度。修法是让脚本自己失败得明确：加互斥锁，提交前检查空闲 slot。」

# 复刻环境搭建：VMware Fusion + Ubuntu Server 24.04（ARM64）

> v1 · 2026-10-25 ｜ 适用于 R1–R7 全部复刻，先按 R1 的需要配置
> 配套：[虚拟机准备](../docs/00-虚拟机准备.md)

## 结论

- **方案**：在 Mac 的 VMware Fusion（已装 25.0.0）里开一台 Ubuntu Server 24.04 虚拟机，不装桌面。所有组件**原生安装**（不套 Docker），单节点部署。
- **关键**：你的 Mac 是 Apple M5，**只能装 ARM64 版的 Ubuntu**，x86 版跑不起来。
- **规格**：6 核、16GB 内存、80GB 动态磁盘。
- **省空间**：Docker Desktop 现在占了 38GB 磁盘。改用虚拟机后，如果 Docker 里没有要留的东西，清理掉它，Mac 的可用空间能从 38GB 翻到约 76GB。清不清理由你决定，也由你来操作。

## 为什么这样选（第一性原理）

| 选择 | 理由 |
|---|---|
| 服务器版，不装桌面 | 省 3–5GB 磁盘和约 1GB 内存；生产服务器本来就没有桌面 |
| 原生安装，不用 Docker | 亲手装、亲手改配置（server.properties、config.yaml、hbase-site.xml、fe.conf / be.conf）。面试被问「怎么部署的、参数怎么调的」时，你有真实经验 |
| 单节点部署 | 32GB 的 Mac 开一台 16GB 虚拟机正合适；以后想练多节点，可以克隆成 3 台 |

## 一、虚拟机规格

| 项 | 建议 | 说明 |
|---|---|---|
| 系统 | Ubuntu Server 24.04 LTS **ARM64** | x86 版在 Apple 芯片上跑不了 |
| CPU | 6 核 | 给 Mac 留 4 核 |
| 内存 | 16GB；做 R1 完整版时调到 20GB | 给 Mac 留 12–16GB |
| 磁盘 | 80GB，动态分配（用多少占多少） | R1 实际约占 25GB |
| 网络 | NAT（与 Mac 共享网络） | Mac 能通过虚拟机的 IP 访问各组件的网页 |

## 二、创建虚拟机（你来操作）

1. **下载镜像**：从 Ubuntu 官方的 [cdimage 24.04 发布目录](https://cdimage.ubuntu.com/releases/24.04/release/) 下载 `ubuntu-24.04.x-live-server-arm64.iso`（x 取最新的小版本）。国内下载慢的话，可以找镜像站的 ubuntu-cdimage 目录。
2. **新建虚拟机**：VMware Fusion → 文件 → 新建 → 把 ISO 拖进去。点「自定义设置」，按第一节改：处理器 6 核、内存 16384MB、硬盘 80GB（不要预分配空间）、网络选「与我的 Mac 共享」。
3. **安装 Ubuntu Server 时这样选**：

   | 安装页面 | 选择 | 原因 |
   |---|---|---|
   | 语言 | English | 服务器上用中文容易乱码 |
   | 安装类型 | Ubuntu Server | 不要选 minimized，它缺很多常用工具 |
   | 网络 | 先用默认的 DHCP | 装完再改成静态 IP |
   | 软件源（Mirror） | `https://mirrors.tuna.tsinghua.edu.cn/ubuntu-ports` | 国内更快；注意 ARM 版用的是 **ubuntu-ports** |
   | 磁盘 | 用整块盘，**取消勾选「Set up this disk as an LVM group」** | 默认的 LVM 方案只给根分区分一半空间，后面还得手动扩容 |
   | 用户名 / 主机名 | 用户名自定，主机名用 `bigdata01` | — |
   | SSH | **勾选 Install OpenSSH server** | Mac 要通过 SSH 连进去 |
   | Featured snaps | 一个都不选 | 省空间 |

4. **装完重启**：登录后执行 `ip a`，记下虚拟机拿到的地址（形如 `172.16.x.y`）。

## 三、装完后的基础配置（在虚拟机里执行）

> 第 1 步（固定 IP）要手动做。第 2–6 步已经写成脚本 `setup/00-base.sh`，可以直接运行，见 [R1 安装脚本说明](../setup/README.md)。下面的手动步骤留作参考，帮你理解脚本做了什么。

1. **固定 IP**：编辑 `/etc/netplan/50-cloud-init.yaml`。网卡名、网段按 `ip a` 看到的改；最后一段取 100，因为 VMware 的 DHCP 一般从 128 开始分配：

   ```yaml
   network:
     version: 2
     ethernets:
       ens160:                          # 换成 ip a 里看到的网卡名
         dhcp4: false
         addresses: [172.16.x.100/24]   # 和 DHCP 拿到的地址同一网段
         routes:
           - to: default
             via: 172.16.x.2            # VMware NAT 的网关固定是 .2
         nameservers:
           addresses: [172.16.x.2]
   ```

   然后执行 `sudo netplan apply`。再新建 `/etc/cloud/cloud.cfg.d/99-disable-network-config.cfg`，写入 `network: {config: disabled}`，否则重启后 cloud-init 会把网络配置改回去。

2. **时区和主机名解析**：执行 `sudo timedatectl set-timezone Asia/Shanghai`；在 `/etc/hosts` 里加一行 `172.16.x.100 bigdata01`。

3. **关闭 swap**（Doris 的要求）：
   - 执行 `sudo swapoff -a`；
   - 注释掉 `/etc/fstab` 里 `/swap.img` 那一行；
   - 删除 `/swap.img`，还能省出 4GB 磁盘。

4. **内核参数和文件句柄数**（Doris 的要求）：
   - 新建 `/etc/sysctl.d/99-bigdata.conf`，写入 `vm.max_map_count=2000000`，然后执行 `sudo sysctl --system`。
   - 新建 `/etc/security/limits.d/99-bigdata.conf`，写入下面两行，然后重新登录：
     ```
     * soft nofile 655350
     * hard nofile 655350
     ```

5. **基础软件**：
   ```bash
   sudo apt update && sudo apt install -y openjdk-17-jdk-headless python3-venv python3-pip mysql-server wget curl unzip net-tools htop
   ```

6. **目录约定**：
   - `/opt/software`：放安装包
   - `/opt/module`：放解压后的组件
   - `/data`：放数据和各组件的数据目录

   ```bash
   sudo mkdir -p /opt/software /opt/module /data && sudo chown -R $USER:$USER /opt/software /opt/module /data
   ```

7. **拍快照**：在 VMware 里拍一个「基础环境」快照，后面装坏了可以一键回滚。

## 四、从 Mac 免密登录

下面两种协作方式都需要这一步。在 **Mac 的终端**里执行：

1. 生成一把专门连这台虚拟机的密钥：
   ```bash
   ssh-keygen -t ed25519 -f ~/.ssh/bigdata01 -C bigdata01
   ```
2. 把公钥放进虚拟机（这一步要输入一次虚拟机的密码）：
   ```bash
   ssh-copy-id -i ~/.ssh/bigdata01.pub 你的用户名@172.16.x.100
   ```
3. 在 `~/.ssh/config` 里加一个别名：
   ```
   Host bigdata01
       HostName 172.16.x.100
       User 你的用户名
       IdentityFile ~/.ssh/bigdata01
   ```
4. 测试：执行 `ssh bigdata01 hostname`，能打印出 `bigdata01` 就通了。

**如果选「我远程安装」**：还要在虚拟机里给你的用户配免密 sudo，因为我不能替你输入密码。只建议在这台练习用的虚拟机上这么做：

```bash
echo "$USER ALL=(ALL) NOPASSWD:ALL" | sudo tee /etc/sudoers.d/$USER
```

## 五、R1 组件规划

| 组件 | 版本线 | 安装方式 | 端口 | 内存上限 |
|---|---|---|---|---|
| JDK | 17（headless） | apt | — | — |
| MySQL | 8.0 | apt | 3306 | `innodb_buffer_pool_size` 设为 256M |
| Kafka | 4.3.2（KRaft 模式，不需要 ZooKeeper） | 官方二进制包 | 9092 | 堆 1G |
| HBase | 2.6.7（单机模式，自带 ZooKeeper） | 官方二进制包 | 16010（网页） | 堆 1G |
| Flink | 1.20.5（standalone） | 官方二进制包 + 4 个连接器 jar | 8081（网页） | JobManager 1.6G + TaskManager 4G（4 个 slot） |
| Doris | 4.0.8 ARM64 版（FE、BE 装在同一台） | 官方 ARM64 二进制包（3.7GB） | 8030（FE 网页）、9030（MySQL 协议） | FE 堆 2G；BE 的 `mem_limit` 设为 4G |
| Python | 3.12（系统自带）+ venv | apt | — | 1–2G |
| 完整版再加 | Flume 1.11、Grafana | 二进制包 / apt | 3000（Grafana） | — |

- **内存合计约 12–13GB**，16GB 的虚拟机够用。
- **两处默认值必须改**：
  - Doris BE 的 `mem_limit` 默认是物理内存的 90%；
  - Doris FE 的默认堆是 8G。
  - 不改的话会把整台虚拟机的内存吃光。
- **启动顺序**：MySQL → Kafka → HBase → Doris FE → Doris BE（第一次要在 FE 里执行 `ALTER SYSTEM ADD BACKEND` 注册 BE）→ Flink。
- **版本**：2026-10-25 已核对下载地址。Kafka 用 4.3.2 而不是 3.9：3.9 已经移到归档站，国内镜像没有，而 4.x 已彻底去掉 ZooKeeper。Doris 用 4.0.8：4.0 系列已经出了 8 个补丁版本，比较稳定，还带向量检索和 AI 函数。HBase 的 Flink 连接器官方最新只发布到适配 1.19 的版本，由冒烟测试验证它在 1.20 上能否用。

## 六、从 Mac 访问和传数据

- **看网页**：Mac 浏览器直接打开 `http://172.16.x.100:8081`（Flink）、`:8030`（Doris）、`:16010`（HBase）。
- **传数据**：UserBehavior 数据集要登录阿里天池下载，所以在 Mac 上下载，再用 `scp` 传到虚拟机的 `/data`。
- **写代码**：代码仓库放在虚拟机里（如 `~/mvp`），在 Mac 上用 VS Code 的 Remote-SSH 直接编辑；推到 GitHub 也在虚拟机里做。

## 七、快照与磁盘

- **快照时机**：基础环境配好后拍一个；R1 组件全部装好、冒烟测试通过后再拍一个。快照会占磁盘，只留最近 2 个。
- **Mac 只剩 38GB**：
  - Docker Desktop 占了 38GB。不再用 Docker 的话，可以在 Docker Desktop 里清理数据，或者直接卸载。先确认里面没有要保留的镜像和数据。
  - 每个复刻做完，删掉原始数据和中间数据，只留代码、结果和 README。
- **动态磁盘不会自动缩小**：在虚拟机里删了文件，Mac 上的虚拟磁盘文件并不会变小。关机后，在 VMware 的虚拟机设置里清理一次磁盘，才能把空间还给 Mac。

## 八、常见问题

| 现象 | 原因 / 解决 |
|---|---|
| 虚拟机建不了或启动报错 | 确认镜像是 arm64 版 |
| 改了静态 IP，重启后又变回去 | 没禁掉 cloud-init 的网络配置（见第三节第 1 步） |
| Doris BE 起不来 | 检查 swap 是否关了、`vm.max_map_count` 和文件句柄数是否生效 |
| 虚拟机很卡 | 检查 Doris BE 的 `mem_limit`、Flink TaskManager 的内存是否超出预算 |
| Mac 打不开组件网页，或连不上 Kafka | 组件只监听了 localhost，要改成监听虚拟机 IP 或 0.0.0.0（如 Kafka 的 `listeners` 和 `advertised.listeners`） |
